# quantsiv-app audit - 2026-10-03

Scope: this repository only (`app/`, `Dockerfile`, `requirements.txt`, `.gitignore`, `README.md`,
and the build plan in `quantsiv_mvp_spec.md`). The landing page is a separate public repo with its
own backlog in its `CLAUDE.md`.

How this was produced: full read of every tracked file plus the untracked
`app/templates/privacy_policy.html`; deterministic checks (Python `ast.parse`, Jinja2 compile and
render, `pip install --dry-run`, `pip-audit` against the OSV/PyPI advisory DB, CycloneDX 1.6
strict-schema validation, WCAG contrast math, FastAPI `TestClient` runs); primary-source reads of
EO 14412, OMB M-26-15 and NIST IR 8547; two adversarial verification passes. Every fix marked
**[tested]** was run against a scratch copy of this repo and behaves as described.

Work through the fixes in the order given in [`REMEDIATION_PLAN.md`](REMEDIATION_PLAN.md).
Finding IDs (`A01`...) are stable; reference them in commits and PRs.

## Summary

- **Nothing runs.** These all fail:
  - the Docker build, at `apt-get` and then at `pip install`;
  - parsing of `app/api.py` and `app/worker.py`;
  - `app/models.py`, which is unparseable in git (UTF-16) and empty in the working copy;
  - the router, which `app/main.py` never mounts;
  - `scan_details.html`, which does not compile;
  - the worker, which has no entry point.

  Only `/`, `/health` and `/static` are served today.
- **The security-critical parts are still placeholders, and the spec's designs for them are
  unsafe.** Placeholder webhook secret, no authentication, planned token-in-URL `git clone`, and
  TLS scanning of hostnames taken from customer repos (SSRF) all need to be designed correctly
  before they are built.
- **The UI shows fabricated data and unsupported claims.** A `Math.random()` findings counter, a
  hard-coded "7 critical, 12 high" row, a default 80 % confidence, and copy promising an
  auditor-ready CBOM and an HNDL data-lifetime score that the code does not produce.
- **The CBOM generator does not produce a CBOM.** Its output has zero components and fails
  CycloneDX 1.6 schema validation. A replacement that passes strict validation is in section 7.
- **Legal surfaces are missing or wrong.** There are no privacy, terms, refund, cookie or legal-notice
  routes. The untracked privacy-policy draft names a placeholder German GmbH at "Musterstrasse 123"
  and makes unsupported security claims, so it must not be published as written.

Severity scale: **P0** blocks the product from installing or running. **P1** must be fixed
before any public launch or first paying customer. **P2** should be fixed (WCAG 2.1 AA failures,
hardening, maintainability). **P3** is polish.

### A03 There is no models module and no package - P0
- **The git copy is unparseable.** `app/models.py` at `HEAD` is UTF-16LE, which is what a fresh
  clone (and any cloud session) gets: `SyntaxError: source code string cannot contain null
  bytes`. The working copy is UTF-8 with a BOM, and both versions contain only `import sys`.
- **The imported models don't exist.** `app/api.py:13` imports `User`, `Installation` and `Scan`.
- **Stray files and folders.** `app/models2.py` contains the single word `test`. Empty untracked
  directories `app/api/`, `app/models/` and `app/worker/` sit next to the modules of the same
  names.
- **No package marker.** `app/` has no `__init__.py`, so it only imports as an implicit namespace
  package.
- **Fix:**
  - Add `app/__init__.py`.
  - Replace `app/models.py` with SQLAlchemy 2.0 declarative models for the six tables in spec §3,
    saved as UTF-8 without a BOM.
  - Delete `app/models2.py` and the three empty directories.

### A04 The router is never mounted, routes are duplicated, and the API docs are public - P0
- **No router.** `app/main.py` never calls `include_router`, so every dashboard, API and webhook

- **Duplicate routes.** `/` and `/health` are defined in both files.
- **Public docs.** `FastAPI()` serves `/docs` and `/openapi.json` by default (verified: HTTP 200).
- **Fix:** see "main.py" in section 7: include the router, define `/` and `/health` once, and

## Security (P0-P2; each finding states its own severity)

### A09 The Docker image cannot be built, and would not run on Railway - P0
- **The build fails at `apt-get`.** `python:3.12-slim` now resolves to Debian trixie, which has no
  `openjdk-17-jre-headless` (`Dockerfile:8-10`). So the build fails before it even reaches the
  `pip install` failure in A07.
  - **Fix:** pin `python:3.12-slim-bookworm`, or install `openjdk-21-jre-headless`, and do it
    only in the worker image.
- **Port ignored.** `Dockerfile:41` hard-codes port 8000, but Railway injects `$PORT`, and the
  `ENV PORT` at `:35` is never used.
- **Missing system packages.**
  - No `git` binary is installed.
  - WeasyPrint needs `libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0`.
- **Other gaps:**
  - `apt` runs without `--no-install-recommends`.
  - Dev tools end up in the production image.
  - There is no `.dockerignore`, so `COPY app/` ships the scratch files from A49.
  - The base image is not digest-pinned.
- **Railway specifics:**
  - Railway ignores a Dockerfile `HEALTHCHECK`. Set `healthcheckPath = "/health"` under
    `[deploy]` in `railway.toml`.
  - uvicorn already enables proxy headers, but only trusts `127.0.0.1`. Set
    `--forwarded-allow-ips` (or `FORWARDED_ALLOW_IPS`) to Railway's proxy.
- **Fix:** use the two-stage web/worker Dockerfile in section 7, and verify it with a CI
  `docker build`.

### A10 Hard-coded placeholder secrets used for real verification - P1
- **Where:** `app/api.py:21-24`.
- **Evidence:** `GITHUB_WEBHOOK_SECRET = "placeholder_webhook_secret"` is the HMAC key the
  webhook handler checks against. If this ships, anyone can forge GitHub events.
- **Fix:** a `pydantic-settings` `Settings` class with required `SecretStr` fields, so startup
  fails when a secret is missing. Commit an `.env.example` (see A21).

### A11 The webhook handler is fragile - P1
- **Where:** `app/api.py:40-71`.
- **Problems:**
  - `hmac.compare_digest` on `str` raises `TypeError` when the header contains non-ASCII
    characters, which becomes a 500 (verified).
  - `request.json()` on a non-JSON body also returns 500.
  - There is no `X-GitHub-Delivery` deduplication, so redeliveries are processed twice.
  - Work runs inline instead of being enqueued. GitHub expects a response within 10 seconds.
  - There is no body-size limit.
- **Fix:** see "Webhook" in section 7: compare bytes, return a fast 202, and enqueue with ARQ
  `_job_id=f"gh-{delivery}"`.

### A12 Installation events crash - P1
- **Where:** `app/api.py:78`.
- **Evidence:** `account_data = payload.get("account")`. In installation events the account is
  at `payload["installation"]["account"]`, so `.get("login")` on `None` raises
  `AttributeError`.

### A13 The push filter accepts tags and nested branch names - P2
- **Where:** `app/api.py:112-115`.
- **Evidence:**
  - `ref.split("/")[2] in ["main","master"]` also matches `refs/tags/main` and
    `refs/heads/main/feature`.
  - It never scans repositories whose default branch has another name.
- **Fix:** skip branch deletions (`payload.get("deleted")`), then compare
  `payload["ref"] == f"refs/heads/{payload['repository']['default_branch']}"`.

### A14 No authentication or authorisation - P1
- **No authentication.** Every dashboard and API route (`app/api.py:124-188`) is open.
- **IDOR.** Scan IDs are sequential integers (spec schema), so any caller could read any tenant's
  scans once a database backs them.
- **Open scan endpoint.** `POST /api/scans` (`:180-188`) lets an unauthenticated caller enqueue
  scans of any public repository, which spends Quantsiv's compute and TLS-scanner capacity.
  - This is not a git argument-injection risk: the name is interpolated inside the URL.
- **Fix:**
  - **Sessions:** after GitHub OAuth, pick one design deliberately: either an opaque session ID in
    an `HttpOnly; Secure; SameSite=Lax` cookie mapped to a `sessions` table (revocable), or
    Starlette's `SessionMiddleware` (a signed client-side cookie).
  - **Authorisation:** a `current_user` dependency, and every query scoped through the user's
    installations (section 7, "Authorisation").
  - **Repository check:** verify `repo_full_name` against the installation's repository list from
    the GitHub API. Keep the regex `^[A-Za-z0-9-]{1,39}/[A-Za-z0-9._-]{1,100}$` as defence in
    depth.
  - **CSRF:** a token on every state-changing request (for htmx, via `hx-headers`).
  - **Optional:** switch to opaque or UUID identifiers.

### A15 The planned clone leaks the installation token - P1
- **Where:** `app/worker.py:119` and spec §3 step 4 plan
  `git clone https://x-access-token:{token}@github.com/...`.
- **Problems:**
  - The token appears in the process list (argv).
  - It is persisted in `.git/config` inside the very tree the scanner reads.
  - It is echoed in git error messages.
- **A second path to the same leak.** `app/worker.py:87-91` stores `str(e)` as `error_message`,
  and `scan_details.html:264` shows it to the user.
- **Fix:** see "Secure clone" in section 7. Pass the token through `GIT_CONFIG_*` environment
  variables, put `--` before the URL, and show users only a fixed message while logging the
  details server-side.

### A16 Untrusted repositories are processed without limits - P1
- **Problems:**
  - No size or time limit.
  - Symlinks can point outside the cloned tree.
  - Submodules and LFS are fetched.
  - The Java scanner runs with the worker's privileges and network access.
- **Fix:**
  - **Clone flags:**
    - `--depth=1 --single-branch --no-tags --no-recurse-submodules`
    - `-c core.symlinks=false -c core.hooksPath=/dev/null`
    - `-c protocol.allow=never -c protocol.https.allow=always`
    - `GIT_LFS_SKIP_SMUDGE=1`
  - **Size check:** read the `size` field (in KB) from `GET /repos/{owner}/{repo}` before
    cloning.
  - **Before scanning:** delete `.git` from the cloned tree.
  - **Sandbox:** run the scanner as a separate process or container with no network, a read-only
    tree, and CPU, memory and time limits.
  - **If the host can't sandbox:** don't offer hosted scanning of private repos; scan inside the
    customer's CI instead (see `quantsiv.md`, "Delivery model").

### A17 SSRF through TLS scanning - P1
- **Where:** `app/worker.py:156-181` and spec §3 steps 7-8 plan TLS scans of hostnames pulled from
  customer config files.
- **The risk:** those hostnames can resolve to loopback, RFC 1918 or link-local addresses,
  including the cloud metadata endpoint `169.254.169.254`.
- **The naive check fails.** `ipaddress.is_global` passes the NAT64 address
  `64:ff9b::a9fe:a9fe`, which reaches the metadata endpoint (verified).
- **Legal exposure.** Actively scanning third-party domains the customer doesn't own is also a
  legal risk.
- **Fix [tested]:** the guard in section 7.
  - Resolve the hostname first, then unwrap any embedded IPv4 (mapped, 6to4, Teredo, NAT64).
  - Require a global, non-multicast address, and connect to the vetted IP with SNI.
  - Use port 443 only.
  - Before resolving, also block internal names such as `*.railway.internal`, `localhost` and
    `*.internal`. On Railway, the realistic SSRF target is the private Redis.
  - Scan only domains the customer has verified with a DNS TXT record. Unverified hosts get at most
    one lightweight handshake, never a full sslyze scan.

### A19 Third-party CDN scripts - P1

### A20 No security headers - P2
- **Where:** `app/main.py` sets none: no CSP, HSTS, `frame-ancestors`, `nosniff`,

- **A strict CSP would break today's templates.** It blocks:
  - the inline scripts at `dashboard.html:201`, `scan_details.html:294` and `scan_live.html:119`;

  - the `style` attribute at `scan_live.html:30`;
  - the Tailwind Play CDN's injected `<style>` (A19).
- **Fix:**
  - **First:** do A19, move the scripts into `/static/js/*.js` using `addEventListener` and

### A21 `.gitignore` hides source files and the env template - P1
- **`*key*` is too broad.** `.gitignore:107` ignores every path containing "key", so a future
  `app/scanner/key_exchange.py` or `tests/test_key_sizes.py` would silently never be committed.
- **The env template is ignored.** `:102` ignores `.env.example`.
- **Clutter.** `.env` is listed twice (`:50`, `:101`), and `:80` reads `cython_debug.sqlite`.
- **Fix:** replace with `*.key`, `*.pem` and `github-app-*.pem`, un-ignore and commit
  `.env.example`, and remove the duplicates.

### A22 Spec §6: Stripe checkout trusts a client-supplied price - P1 (design)
- **Problem:** `create_checkout_session(price_id: str)` passes whatever the client sends, so a
  user can subscribe at any active price in the account.
- **Fix:**
  - Accept only a plan name, and map it to a price ID server-side (section 7).
  - Verify Stripe webhooks with `stripe.Webhook.construct_event`, which checks the signature and
    the timestamp tolerance.
  - Derive `user.plan` from the subscription's price ID, never from client data.

### A23 Spec §7: share links cannot be revoked - P1 (design)
- **Problems:**
  - A stateless HMAC token cannot be revoked before it expires.
  - The token lands in uvicorn and platform access logs.
  - The `Referer` exposure is smaller than it looks: browsers default to
    `strict-origin-when-cross-origin`, so the path isn't sent cross-site.
- **Fix:**
  - Store tokens as random 32-byte values, hashed, in a `share_links` table (`scan_id`,
    `expires_at`, `revoked_at`).
  - Mask `/share/` paths in access logs.
  - Set `Referrer-Policy: no-referrer` on share pages as defence in depth.

### A24 Unneeded authentication dependencies - P1
- **python-jose:** not needed. Its 3.4.0 and 3.5.0 releases fix the known CVEs, but PyJWT covers
  everything Quantsiv needs.
- **passlib:** stale (no release since 2020, and it breaks with bcrypt 4.1 and later), and
  pointless, since there are no passwords: login is GitHub OAuth only.
- **Fix:** drop both, and use PyJWT only for the GitHub App's RS256 JWT. For the session design,
  see A14.

### A25 Personal data printed to stdout - P1
- **Where:** `print()` calls output GitHub account names and repo names at `app/api.py:87`,
  `:98-100` and `:120`, and throughout `worker.py`.
- **Fix:** use `logging` with levels, keep personal data out of INFO, and set retention to match
  the privacy policy.

## P1 - product correctness and claims

### A26 The "CBOM" generator does not produce a CBOM - P1
- **Where:** `app/worker.py:222-274`.
- **Evidence (verified):** the output has **zero components** and **fails** CycloneDX 1.6 strict
  validation. It also has these defects:
  - Findings are stuffed into `vulnerabilities`, with invented CVSSv31 scores (`:258-261`) and a
    fake `CVE-2022-XXXX` reference (`:267`).
  - `serialNumber` is `"urn:uuid:placeholder"` (`:232`).
  - TLS findings get the ID `VULN-None-None` (`:251`).
  - `.upper()` crashes when a severity is `None` (`:261`).
  - It uses the deprecated `datetime.utcnow()` (`:235`) and the deprecated `metadata.tools` array
    form.
- **Fix [tested]:** the `build_cbom` function in section 7. It emits `cryptographic-asset`
  components with `cryptoProperties`, a valid `urn:uuid` and file/line evidence, and passes
  `JsonStrictValidator(SchemaVersion.V1_6)` with no warnings.

### A27 The planned scan engine has no such interface - P1 (design)
- **Where:** `Dockerfile:22-25` and spec §3 plan
  `java -jar cbomkit-lib.jar scan --input ... --format cyclonedx-json`.
- **What cbomkit-lib really is** (github.com/cbomkit/cbomkit-lib, Apache-2.0, now under the Linux
  Foundation's PQCA after IBM donated CBOMkit): a **Java library** with an indexer and a scanner
  per language. It has no CLI.
- **What it covers.** Its README says "currently we support the programming languages java and
  python". **No Go.**
  - **Python:** the detection underneath, sonar-cryptography, covers pyca/cryptography only. So
    the worker's own test sample (`from Crypto.PublicKey import RSA`, which is PyCryptodome) would
    not be detected.
  - **Java:** accuracy depends on build artifacts. Source-only Java scanning is **disabled by
    default** and needs compiled classes and jars, which a fresh server-side clone does not have.
- **Fix:**
  - Choose an engine in `REMEDIATION_PLAN.md` decision D2. Either wrap cbomkit-lib in a small Java
    main built as a pinned, checksummed fat jar, or run CBOMkit's published action or plugin.
  - Add your own PyCryptodome rules.
  - Remove Go from every claim until a Go scanner exists.
  - Prefer scanning inside the customer's CI, **after** their build, where Java artifacts exist
    (see "Delivery model" in `quantsiv.md`).

### A28 The "HNDL exposure score" doesn't exist - P1
- **Where:** `app/worker.py:202-220` computes the score from severity counts only.
- **The contradiction.** `dashboard.html:100-101` promises "an HNDL exposure score that ranks
  findings by how long the protected data must stay secret", but no data-lifetime input exists
  anywhere.
- **Fix:** either add a data-classification input (per repo or service, with a retention or
  confidentiality lifetime) and score against it, or change the copy to "severity score".

### A29 The UI shows fabricated data as real - P1
- **The fakes:**
  - `scan_details.html:294-309`: a `Math.random()` "Findings so far" counter.
  - `scan_details.html:167`: `(finding.confidence or 0.8)` shows a made-up 80 %.
  - `dashboard.html:137-162`: a hard-coded "example/repo / 73 / 7 critical, 12 high / Just now"
    row. Spec §5 itself requires a demo scan to be labelled as a demo.
  - `dashboard.html:74-75`: an undefined "Compliance Rate".
  - `app/api.py:134-149` and `:170-178` return a fake scan for any ID.
  - `app/api.py:184-188` answers "Scan queued" without queueing anything.
- **Fix:**
  - Delete the random counter.
  - Render `—` when `confidence is none`.
  - Render scans from the database, with an empty state.
  - Label any demo "Demo scan of a public repository".
  - Return 404 or 501 until real data exists.

### A30 Risk text and migration guidance are inaccurate - P1
- **HNDL text on signatures.** `scan_details.html:196-198` tells users every finding is being
  harvested now, including signature findings like the sample "Token signing". HNDL threatens
  confidentiality (key establishment and encryption); a signature's risk is future forgery.
- **Unsourced timeline.** `:193` states "Timeline for exploitation: ~2030-2035" without a source.
- **Wrong mapping.**
  - `:218-223` maps RSA only to "ML-KEM for key exchange", even when RSA is used for signing.
  - ECDH, X25519 and EdDSA get no guidance at all.
- **AES-128 misclassified.** Spec §3 step 6 classifies AES-128 as quantum-vulnerable, which
  contradicts NIST IR 8547 (ipd): symmetric primitives with at least 128 bits of security meet
  Category 1.
- **Fix:** map guidance by CycloneDX primitive (section 7, "Migration guidance"), and show the
  HNDL text only for `key-agree`, `kem` and `pke`. Cite a source for any timeline, or drop it.
  Remove AES-128 from the vulnerable list.

### A31 Copy and README claim features that don't exist - P1
- **Dashboard.** `dashboard.html:99-102` says every scan yields an auditor-ready CycloneDX 1.6
  CBOM, while `:184` sells "CBOM export" as a paid feature.

## Additional findings from adversarial verification

### A50 The worker service cannot start - P0
- **Where:** `app/worker.py:17` defines only `class ScanWorker`. There are no ARQ
  `WorkerSettings`, no `functions` list and no `redis_settings`.
- **Why it matters:** `README.md:84` (as of commit b38b80b) and spec §3 start the worker with
  `python -m arq app.worker.WorkerSettings`, which doesn't exist.
- **Related:** `app/api.py:18` instantiates `ScanWorker()` at import time instead of enqueueing
  jobs.
- **Fix:** ARQ job functions plus `WorkerSettings` (section 7). The API enqueues through an
  `ArqRedis` pool created at startup.

### A51 Spec §3: web and worker cannot share a SQLite file on Railway - P1 (design)
- **The plan:** separate `web` and `worker` services, plus a volume holding `/data/quantsiv.db`.
- **The problem:** a Railway volume attaches to a single service, so the worker could not write
  results the web service can read.
- **Fix:** use Postgres (Railway Postgres, `DATABASE_URL`, SQLAlchemy and Alembic) from day one.

### A52 Installation tokens are neither down-scoped nor revoked - P2
- **Where:** spec §3 step 3 (`app/worker.py:106` is the stub).
- **The problem:** the token is minted with no request body, so for its full hour it carries
  every repository and permission the installation has.
- **Fix:**
  - Request `{"repositories": [repo_name], "permissions": {"contents": "read", "metadata": "read"}}`.
  - Call `DELETE /installation/token` in the `finally` block after cloning.

### A53 Spec §3 step 6 ranks signing above key establishment, inverting the HNDL thesis - P1
- **The rule:** "critical: RSA/ECDSA in auth/signing/token paths; high: ... key exchange or
  encryption".
- **Why it's backwards:**
  - Harvest-now-decrypt-later threatens key establishment and encryption of long-lived data, not
    signatures.
  - EO 14412's deadline for key establishment (31 Dec 2030) also falls a year before the one for
    signatures (31 Dec 2031).
- **Fix:** rank by CycloneDX primitive and declared data lifetime.
  - **`kem`, `key-agree`, `pke`:** critical when they protect data whose secrecy must outlast the
    threat horizon.
  - **Signatures:** ranked by the signature deadline and the artifact's lifetime (for example
    code- and firmware-signing roots high, short-lived tokens medium).
  - Update `worker._compute_risk_score` and the copy (A28, A30) to match.

### Webhook (A11, A12, A13)

```python
import hashlib
import hmac
import json

from fastapi import Depends, HTTPException, Request

from app.config import Settings, get_settings

MAX_BODY = 25 * 1024 * 1024  # GitHub caps webhook payloads at 25 MB


@router.post("/webhook/github", status_code=202)
async def github_webhook(request: Request, settings: Settings = Depends(get_settings)):
    if int(request.headers.get("content-length") or 0) > MAX_BODY:
        raise HTTPException(413)
    body = await request.body()
    secret = settings.github_webhook_secret.get_secret_value().encode()
    expected = b"sha256=" + hmac.new(secret, body, hashlib.sha256).hexdigest().encode()
    received = request.headers.get("X-Hub-Signature-256", "").encode("latin-1")
    if not hmac.compare_digest(received, expected):  # bytes: no TypeError on odd input
        raise HTTPException(401, "invalid signature")
    delivery = request.headers.get("X-GitHub-Delivery")
    event = request.headers.get("X-GitHub-Event")
    if not delivery or not event:
        raise HTTPException(400, "missing GitHub headers")
    try:
        payload = json.loads(body)
    except ValueError:
        raise HTTPException(400, "body is not JSON")
    # ARQ refuses a second job with the same id, so redeliveries are processed once
    await request.app.state.arq.enqueue_job(
        "handle_github_event", event, payload, _job_id=f"gh-{delivery}"
    )
    return {"status": "queued"}


# worker side

    if event == "installation" and payload.get("action") == "created":
        account = payload["installation"]["account"]  # not payload["account"]
```

### Secure clone (A15, A16)

```python
import asyncio
import base64
import logging
import os
import re

logger = logging.getLogger(__name__)
REPO_RE = re.compile(r"[A-Za-z0-9-]{1,39}/[A-Za-z0-9._-]{1,100}")


class ScanError(Exception):
    """Its message is safe to show to users."""


async def clone_repository(repo_full_name: str, token: str, dest: str, timeout: int = 120) -> None:
    if not REPO_RE.fullmatch(repo_full_name):
        raise ScanError("Invalid repository name")
    auth = base64.b64encode(f"x-access-token:{token}".encode()).decode()
    env = {
        "PATH": os.environ["PATH"],
        "GIT_CONFIG_NOSYSTEM": "1",
        "GIT_CONFIG_GLOBAL": os.devnull,
        "GIT_TERMINAL_PROMPT": "0",
        "GIT_ASKPASS": "/bin/true",
        "GIT_LFS_SKIP_SMUDGE": "1",
        # git >= 2.31 reads config from the environment: the token never reaches argv,
        # the URL, or .git/config inside the tree the scanner reads
        "GIT_CONFIG_COUNT": "1",
        "GIT_CONFIG_KEY_0": "http.https://github.com/.extraheader",
        "GIT_CONFIG_VALUE_0": f"Authorization: Basic {auth}",
    }
    proc = await asyncio.create_subprocess_exec(
        "git", "-c", "core.symlinks=false", "-c", "core.hooksPath=/dev/null",
        "-c", "protocol.allow=never", "-c", "protocol.https.allow=always",
        "clone", "--depth=1", "--single-branch", "--no-tags", "--no-recurse-submodules",
        "--", f"https://github.com/{repo_full_name}.git", dest,
        env=env, stdout=asyncio.subprocess.DEVNULL, stderr=asyncio.subprocess.PIPE,
    )
    try:
        await asyncio.wait_for(proc.communicate(), timeout)
    except asyncio.TimeoutError:
        proc.kill()
        await proc.wait()
        raise ScanError("Cloning timed out")
    if proc.returncode != 0:
        # git's stderr can echo URLs and headers: log the exit code, never the text
        logger.warning("git clone failed for %s (exit %s)", repo_full_name, proc.returncode)
        raise ScanError("Could not clone the repository")
```

Store only `ScanError` messages in `scans.error_message`. Everything else becomes
"Internal error" and goes to the logs.

```python
import ipaddress
import socket

_NAT64 = (ipaddress.ip_network("64:ff9b::/96"), ipaddress.ip_network("64:ff9b:1::/48"))


def _embedded_ipv4(ip: ipaddress.IPv6Address) -> ipaddress.IPv4Address | None:
    if ip.ipv4_mapped:
        return ip.ipv4_mapped
    if ip.sixtofour:
        return ip.sixtofour
    if ip.teredo:
        return ip.teredo[1]
    if any(ip in net for net in _NAT64):
        return ipaddress.IPv4Address(int(ip) & 0xFFFFFFFF)
    return None


def is_public_ip(value: str) -> bool:
    try:
        ip = ipaddress.ip_address(value)
    except ValueError:  # e.g. scoped "fe80::1%eth0"
        return False
    if ip.version == 6:
        v4 = _embedded_ipv4(ip)
        if v4 is not None and not (v4.is_global and not v4.is_multicast):
            return False
    return ip.is_global and not ip.is_multicast


_BLOCKED_SUFFIXES = (".internal", ".railway.internal", ".local", ".localhost", ".lan")


def resolve_scan_target(host: str, port: int = 443) -> str:
    """Return a vetted public IP; connect to it with SNI=host so DNS cannot be rebound."""
    if port != 443:
        raise ValueError("only port 443 is scanned")
    name = host.lower().rstrip(".")
    if name == "localhost" or name.endswith(_BLOCKED_SUFFIXES):
        raise ValueError(f"{host} is an internal name")
    ips = sorted({info[4][0] for info in socket.getaddrinfo(host, port, type=socket.SOCK_STREAM)})
    if not ips or not all(is_public_ip(ip) for ip in ips):
        raise ValueError(f"{host} resolves to a non-public address")
    return ips[0]
```

### CBOM builder (A26) [tested: passes CycloneDX 1.6 strict validation, no warnings]

```python
from cyclonedx.model.bom import Bom
from cyclonedx.model.component import Component, ComponentType
from cyclonedx.model.component_evidence import ComponentEvidence, Occurrence
from cyclonedx.model.crypto import (
    AlgorithmProperties, CryptoAssetType, CryptoFunction, CryptoPrimitive, CryptoProperties,
)
from cyclonedx.output.json import JsonV1Dot6

PRIMITIVE = {"signature": CryptoPrimitive.SIGNATURE, "kex": CryptoPrimitive.KEY_AGREE,
             "pke": CryptoPrimitive.PKE, "kem": CryptoPrimitive.KEM}
FUNCTIONS = {"signature": [CryptoFunction.SIGN, CryptoFunction.VERIFY],
             "kex": [CryptoFunction.KEYDERIVE],
             "pke": [CryptoFunction.ENCRYPT, CryptoFunction.DECRYPT],
             "kem": [CryptoFunction.ENCAPSULATE, CryptoFunction.DECAPSULATE]}


def build_cbom(findings: list[dict], repo_full_name: str) -> str:
    bom = Bom()  # valid urn:uuid serial number and tz-aware timestamp by default
    bom.metadata.component = Component(
        name=repo_full_name, type=ComponentType.APPLICATION, bom_ref="root"
    )
    for i, f in enumerate(findings):
        family = f.get("algorithm_family") or "unknown"
        algo = AlgorithmProperties(
            primitive=PRIMITIVE.get(family, CryptoPrimitive.UNKNOWN),
            parameter_set_identifier=str(f["key_size"]) if f.get("key_size") else None,
            crypto_functions=FUNCTIONS.get(family, []),
            nist_quantum_security_level=0 if not f.get("quantum_safe") else None,
        )
        evidence = None
        if f.get("file_path"):
            evidence = ComponentEvidence(
                occurrences=[Occurrence(location=f["file_path"], line=f.get("line_number"))]
            )
        bom.components.add(Component(
            bom_ref=f"crypto-{i}",
            name=f"{f['algorithm']}-{f['key_size']}" if f.get("key_size") else f["algorithm"],
            type=ComponentType.CRYPTOGRAPHIC_ASSET,
            crypto_properties=CryptoProperties(
                asset_type=CryptoAssetType.ALGORITHM, algorithm_properties=algo
            ),
            evidence=evidence,
        ))
    bom.register_dependency(bom.metadata.component, list(bom.components))
    return JsonV1Dot6(bom).output_as_string(indent=2)
```
